# 00 · corrective-rag 项目全景：它是什么、为什么这么设计

> **本文只讲全景**：这个项目作为一个完整系统是什么样、每个部件为什么存在、效果怎么证明。
> 不讲施工进度（进度看 `README.md`，验收标准看 `docs/01-项目计划书.md`）。
>
> **事实分级约定**：【官方】= 论文/库官方文档原文；【实测】= 本机跑过命令验证；
> 【第三方】= 他人转述；【未验证】= 设计判断，动工时需复核。

---

## 0. 一句话全景

这个项目要做的事：**给"查资料回答问题的 AI"加一道质量门和一条返工线**——检索回来的资料先过滤相关性，再判断"合起来够不够回答这个问题"；不够就把问题改写一下重查，最多 3 次；3 次还不过，就诚实回答"资料里没有"，而不是硬编。

它模仿两篇论文的方法（CRAG 的纠错循环 + Adaptive-RAG 的查询路由），用两个公开中文基准把每一环的效果量化出来。最终产出是一个能演示的系统，加一组经得起面试追问的数字。

---

## 1. 要解决的问题：朴素 RAG 的三种死法

先用一个具体场景走一遍（本文所有概念都挂在这个场景上）：

> 学生在系统里问："**实验课的安全规程是什么？**"

**朴素 RAG**（现在满世界都是的那种）干活分三步：

1. **建库**：提前把学校资料切成一页页小块，每块算成一个向量存起来
2. **检索**：学生提问 → 问题也算成向量 → 找出最相似的 4 个块
3. **生成**：把这 4 个块连问题一起塞给大模型 → 生成答案

三步里**没有任何一步检查"我找到的资料对不对、够不够"**。于是有三种死法：

**死法一：资料不相关，照样硬答。** 问"安全规程"，向量检索返回了"课程评分标准""补考流程"——语义上都跟"课"有关，但答不了这个问题。大模型不知道资料不相关，它会照着烂资料一本正经地编一段"安全规程"。用户看到的是一段流畅、自信、错误的答案。

> 类比：你用 grep 搜关键词，搜不到会返回空；RAG 是 grep 到一堆烂条目，也照样给你写报告。
> **没有质量门，错误答案是静默的**——这比"搜不到"更危险。

**死法二：问法不好，检索落空。** 学生实际问的是"那个化学实验要注意啥"——没有"安全规程"这个词，检索可能一路跑偏。人遇到这种情况会换几个关键词再搜一遍，朴素 RAG 不会，它只认第一轮的结果。

**死法三：资料里真的没有。** 学校根本没发过安全规程文档。唯一正确的答案是"资料里没有，建议联系实验课老师"——但朴素 RAG 没有任何机制知道自己"没有"，它只会从最相似的边角料里硬凑一个答案。

这个项目就是给这三种死法各装一道闸门。

## 2. 全景图：一条带质检和返工的流水线

```
retrieve → rerank → judge ──sufficient──→ generate → END
   ↑                    │
   │                    └─insufficient─→ iteration<MAX? ─yes→ rewrite ─┐
   │                                                          └no──→ abstain → END
   │                                                                    │
   └────────────────────────────────────────────────────────────────────┘
```

七个部件，每个都在回答"没有它会怎样"：

| 部件 | 干什么 | 没有它会怎样 |
|---|---|---|
| retrieve | 向量检索粗排，取 top20 候选 | 没有候选集，后面全是空中楼阁 |
| rerank | 精排模型逐篇细读，精选 top4 | 进 prompt 的 4 篇里混着"相关但答不了"的篇目，大模型被带偏 |
| judge | 判断 4 篇**合起来**够不够答这道题 | 系统没有"资料不合格"这个概念，纠错循环永远不被触发 |
| rewrite | 不够就改写问题再查一轮 | 纠错循环只剩"原地重试"（结果一模一样），没有"纠错" |
| abstain | 3 次还不够，诚实说不知道 | 要么硬编（幻觉），要么循环跑飞（成本爆炸） |
| generate | 带着引用生成答案 | 答案无法核对出处 |
| trace | 每步评分、延迟、成本落盘 | 简历上每个数字都没有出处 |

两个关键设计决定：

- **abstain 是一等终态，不是异常分支**。宁可不答，不牵强。类比：异常处理里显式的兜底分支，而不是 catch-all 吞掉所有异常假装成功。
- **MAX_ITERATIONS=3 封顶**。成本和延迟必须有上限。它和 abstain 是一对：一个封顶成本，一个保证出口。

**为什么用状态机而不是 while 循环**：纠错逻辑的本质是"多分支 + 可回溯 + 有终止条件"。状态机把每个分支、每步 trace、终止条件都画成图上的显式节点和边；while 循环的重试逻辑散落在代码里，加一个分支要通读全文还容易漏 trace。类比：画流程图 vs 面条代码——面试一张图讲完。

## 3. 名词逐个拆

每个概念按固定顺序讲：**它解决什么问题 → 举个具体例子 → 最后才给名字 → 没有它会怎样**。名字是附赠的标签，不是门槛。

### 3.1 RAG（检索增强生成）

- **问题**：大模型有两样不行——不知道你学校的私有资料；不知道的事它会编，而不是说不知道。
- **例子**：直接问模型"实验课安全规程"，它要么说不知道，要么编一个通用的。
- **名字**：RAG = 先检索（Retrieval）相关资料，再连问题一起生成（Augmented Generation）。
- **没有它会怎样**：幻觉、答非所问。本项目是 RAG 的一种加固版——RAG 管"找到资料"，本项目管"找到的资料不过关就不许用"。

### 3.2 切分（chunk）

- **问题**：prompt 装不下全部资料；而且不切的话，检索的最小单位是"整份文档"，太粗。
- **例子**：把《学生手册》按标题和段落切成几百字一块，每块独立检索。
- **名字**：chunk = 检索的最小单位。
- **没有它会怎样**：要么塞不进 prompt，要么检索到一整本书却只有一句相关。
- **工程实际**：中文分隔符优先级自己掌控（自写递归切分器）——408 题都整理过的人写得来这个。

### 3.3 embedding（向量）与余弦相似度

- **问题**：关键词检索不懂同义词。学生搜"口令"，资料写的是"密码"——精确匹配搜不到，但它们是一个意思。
- **例子**：embedding 模型把"实验课安全规程"和"化学实验注意事项"各自变成一个向量，两个向量夹角很小，系统就认为它们"说的是同一件事"。
- **名字**：embedding = 把文本变成向量；语义近的文本，向量就近；用余弦相似度量"近不近"。
- **类比**：哈希要求精确命中；embedding 是"支持模糊匹配的索引"。
- **没有它会怎样**：用户换一种说法就检索不到。
- **坑**【官方约定】：bge 这类模型，**问题侧必须加指令前缀、文档侧不加**，漏加掉点。

### 3.4 混合检索 + RRF

- **问题**：向量检索也有死穴——专有名词、编号、罕见词（比如"R6.3 接口规范"），向量觉得这些词"谁也不认识谁"，关键词索引却能一击即中。
- **例子**：问"R6.3 是什么"——向量路可能跑偏，关键词路精确命中。两路都要有。
- **解法**：两路各查一次，合并结果。RRF（倒数排名融合）**不看分数看名次**，每路贡献 1/(60+名次)。
- **类比**：比赛按"预赛名次积分 + 决赛名次积分"算总分，不直接比分——因为两个量程的分数量纲不同，名次才是可比的。
- **没有它会怎样**：任一路的死穴没人补。

### 3.5 rerank（重排）

- **问题**：向量粗排快但糙——它把问题和文档**分开**算向量，看不到"问题里的词和文档里的词怎么互动"。好比只看书名猜内容，没翻开过。
- **例子**：粗排取前 20；精排模型把"问题 + 单篇文档"拼在一起逐篇细读打分，取前 4。
- **类比**：数据库先走索引定位候选集，再回表逐行精确过滤；或者初赛进决赛。
- **名字**：rerank = 用更准但更慢的模型对候选集重新排序。
- **没有它会怎样**：进 prompt 的 4 篇里混着"相关但答不了"的篇目，大模型被带偏，死法一发生。
- **工程实际**：精排模型跑在 CPU 上——比调大模型便宜且稳，这就是它前置的理由：先用便宜的闸门滤掉大部分噪音，再用贵的判断。

### 3.6 judge（充分性判断）——整个系统的质量门

- **问题**：rerank 逐篇判"这篇相关不相关"（局部），但 **4 篇合起来够不够回答这个问题**（全局）是另一个问题。
- **例子**：三篇文档分别讲了实验目的、材料清单、评分标准——逐篇都"相关"，合起来答不了"安全规程"。
- **名字**：judge = 判断检索结果整体充分性的节点；输出 0/1/2 三档（不够 / 边缘 / 够）。
- **为什么是 0/1/2 而不是 1-10**：大模型打 1-10 分校准极差，分数全堆在 7-8，阈值切上去噪声大；三档足够表达门控决策且稳定。
- **类比**：单元测试测局部正确性，集成测试测"合起来能不能用"——两层质检各司其职，这就是 CRAG 论文之后 RAG 评测的核心设计。
- **没有它会怎样**：系统没有"资料不合格"这个概念，第 2 节那张图会退化成一个大环——永远在检索生成，永远不返工。
- **工程实际**：两个实现、同一接口——有 API key 用大模型 judge，没 key 用规则基线照样跑通全链路；规则基线还兼作对照组（"我的 LLM judge 比规则基线多救回多少"本身就是面试素材）。

### 3.7 查询改写（PRF，伪相关反馈）

- **问题**：第一轮检索失败（judge 说不够），原地重试结果一模一样——同样的词搜同样的库。
- **例子**：问"那个实验要注意啥"，首轮返回的文档里高频出现"护目镜""通风橱""废液处理"——用这些实词扩展原问题再搜一轮，命中率就上来了。
- **名字**：PRF = 用首轮检索结果里的高频实词扩展查询。这是 1980 年代至今仍在用的经典信息检索技术（RM3 的简化版），论文依据充分，不是拍脑袋。
- **类比**：你搜一个东西，从第一页结果里抓几个更准的关键词，再搜一遍。
- **风险与自检**：改写是纠错循环里**最危险**的一步——把"它"的指代消解错了，整个查询带偏，比不改写更糟。所以改写后要检查新旧查询的重合度，**漂移过度就放弃改写、用原查询重试：宁可原地重试，不要带偏**。
- **没有它会怎样**：纠错循环只剩"重试"没有"纠错"。

### 3.8 拒答（abstain）

- **问题**：3 次改写重试还不够，资料里就是没有。
- **例子**：学生问"保研政策"，知识库里只有教务通知——正确行为是说"资料里未找到"，并附上尝试记录。
- **设计**：abstain 是一等终态，不是异常分支。宁可不答，不牵强。
- **没有它会怎样**：要么硬编（幻觉），要么循环跑飞（成本爆炸）。

### 3.9 公开基准 + A/B（怎么证明有效）

- **问题**："我感觉纠错循环有用"不是证据，面试一问就穿。
- **做法**：公开人工标注基准 + 同题对比——同一批问题，naive（单趟直生）vs corrective（全闭环），报 "X% → Y%"，**不写"提升了 XX"**。
- **没有它会怎样**：所有"提升"都是形容词；简历上的数字没有出处。
- 详见第 5 节。

## 4. 论文血缘：抄谁、改了什么

| 论文 | 主张 | 本项目抄了什么 |
|---|---|---|
| CRAG（arXiv:2401.15884，2024-01）【官方】 | 检索结果先评估，不合格走纠错（改写 / 换知识源 / web 兜底） | 纠错循环的骨架：评估 → 策略池 |
| Adaptive-RAG（arXiv:2403.14403，NAACL 2024）【官方】 | 按查询复杂度路由：简单问题直答，复杂问题才检索 | 查询路由节点的设计 |

**对最初设想的五处修正**（设计演进的痕迹，每处都是"想清楚了"）：

1. "Agent 节点"正名为 **query router**——它就是个二分类器（Adaptive-RAG 的 classifier），不是 agent；
2. 评分节点拆成 **rerank + judge 两层**——相关性用精排模型，充分性才用大模型（见 3.6）；
3. 纠错从"只会重写查询"扩成**策略池**（重写 / 切混合检索 / 拒答）——CRAG 原文也是三态纠错 + web 兜底；
4. 补 **abstain 终态和 max_iterations**——最初画的状态机是个死循环，没有出口；
5. 评测从自建标注集改为**公开基准**（见第 5 节）。

**对外描述的诚实声明**：不自称 "Agentic RAG"。那是伞术语（综述 arXiv:2501.09136），底下装着 reflection / planning / tool use 一整套模式，本项目只实现其中两类，背伞被追问定义就失分。按"谁决定步骤序列"的判定线，**本项目是 workflow**：每一步走哪条路由，由判断节点和代码决定，不是模型自主规划——这个区分在面试里是加分项，含糊其辞才是减分项。

## 5. 评测设计：每个数字怎么来

### 两个公开基准，分工明确

| 基准 | 管什么 | 关键事实 |
|---|---|---|
| DuReader-retrieval（arXiv:2203.10232，百度）【官方】 | **检索层** | dev 2,000 条人工标注 query / 100,001 passage / 9,839 条二值 qrels【实测：落地对账零差错】。论文基线：BM25 MRR@10 **21.03** → 双编码器 **53.96** → +cross-encoder **74.21**【官方：论文数字，作对照锚点】 |
| RGB（arXiv:2309.01431，AAAI 2024，中科院）【官方】 | **生成层** | 四大能力：噪声鲁棒 / 负例拒绝 / 信息整合 / 反事实鲁棒——**一一对应纠错循环的四个策略** |

DuReader 的 qrels 是**真人标注**——judge 的一致性拿它验，比自标强；RGB 专测"拒答 + 抗噪"——正好打在第 2 节图的 abstain 分支上。

### 指标定义（每个数字的算法，杜绝"提升了效果"）

| 指标 | 算法 |
|---|---|
| Recall@k / hit@k | qrels 是二值相关，标准 nDCG 会退化，所以报 Recall 和 hit |
| 答案可用率 / 离题率 | LLM judge 初判 + 人工抽 20% 校准 |
| 拒答恰当率 | **C 类（应拒答）的拒答比例 与 A+B 类（应回答）的误拒比例，分开报，不合并成一个数** |
| judge 一致性 | judge 的 0/1/2 与人工 qrels 算 agreement（目标 ≥75%，**自定目标，非行业标准**） |
| 平均重写次数 / 重试触发率 | trace 统计 |
| p50 端到端延迟 / token per query | trace 统计 |

### 协议纪律（比指标本身更重要）

- **dev split 调参**（reranker 阈值、judge 阈值），**test split 只跑一次最终 A/B**——反复在 test 上调参等于把测试集当训练集；
- A/B 口径：同一批问题、同题对比，写成 "X% → Y%"，不写"提升了 XX"；
- **污染披露**：embedding 模型（2023-08 训练）晚于这些基准（2022-2023 构建），可能存在训练数据污染 → **A/B 的 delta 比绝对值可信**。面试主动说这条，说了是加分。

### 为什么不用自建标注集

标注工时是整个项目最不可压缩的部分；公开基准带人工标注的 ground truth，还有论文公布的可比基线——面试语境下"DuReader-retrieval test split"比"我自己标了 100 条"硬得多。

## 6. 技术选型全景（每个选型的理由）

| 组件 | 选型 | 为什么 | 坑 |
|---|---|---|---|
| 编排 | **LangGraph 单独用**，不装 langchain 全栈 | 状态机 + 条件边 + checkpointer 正好表达纠错循环 | LangChain 抽象层版本 churn 大，面试讲不清依赖反而失分 |
| 向量检索 | **FAISS**（IndexFlatIP + L2 归一化 = 精确余弦） | 零版本意外、完全可讲清 | chroma 弃用原因：默认 embedding function 会偷偷调 OpenAI API，必须显式覆盖才安全 |
| embedding | bge-small-zh（约 100MB，512 维） | 中文效果好、体积小 | query 侧必须加指令前缀【官方约定】 |
| reranker | bge-reranker-base（CPU） | 相关性过滤比 LLM 便宜且稳 | 不够再换 bge-reranker-v2-m3 |
| LLM | DeepSeek API（OpenAI 兼容协议） | 便宜、国内可达【实测：端点可达】 | 无 key 时全链路 stub 照跑，验证链路不依赖 key |
| 切分 | 自写递归切分 | 中文分隔符优先级自己掌控 | 会产生少量"纯小标题"短 chunk，需清洗 |
| 评测 judge | **自写**（定义对齐 ragas 公开文档） | ragas 装不上：依赖的 vertexai 模块被上游删除，import 即炸【实测】 | 四个指标本就是 LLM judge 口径，自写完全可控 |
| 前端 | gradio | 聊天 demo 最省事 | — |
| trace | 自写 JSONL | 免 LangSmith 账号、数据在本机 | **所有简历数字的唯一出处** |

## 7. 六阶段全景（每阶段回答一个问题）

| 阶段 | 回答什么问题 | 验收标准 | 产出对应 |
|---|---|---|---|
| P0 环境骨架 | 机器能跑吗 | import 全绿 + 模型落盘 | 地基，无直接简历点 |
| P1 naive RAG | 全链路通吗 | 10 个问题有答案、每个引用打开确实支撑答案 | 简历第一句："实现了从文档加载到答案生成的全链路，答案强制携带可核对引用" |
| P2 评测 + 基线 | 怎么证明有效 | baseline 数字落盘——**没这组数字不许进 P3**，没有 baseline，提升无法证明 | 面试问"你怎么证明有效"的第一张牌 |
| P3 质量门控 | judge 可信吗 | judge 一致性报出（目标 ≥75%）；rerank 前后 context precision 对比；单 query 成本对比 | "评分节点怎么设计的"完整答案：为什么 rerank 前置、为什么 0/1/2、误差率怎么估 |
| P4 纠错闭环 | 闭环比单趟好吗 | A/B 报告（test split，一次）；≥5 个拒答案例人工检查"拒得对"；重写前后 query 漂移抽检 | 简历主 bullet（数字只能来自 test A/B，不是恒真式） |
| P5 多轮对话 | 带指代的追问散不散 | 5 轮连贯追问；token 对比**必须写明"第几轮、窗口多大下实测"** | 多轮上下文管理 bullet |
| P6 定稿 | 每个数字有出处吗 | **每个简历 bullet 的数字都能在 trace JSON 里找到；找不到出处的删掉** | 简历定稿 + demo |

## 8. 风险全景（设计时就知道会死在哪）

| 风险 | 对策 |
|---|---|
| 数据污染（embedding 与基准时间线重叠） | 主动披露；delta 比绝对值可信 |
| 口径说不清（nDCG vs Recall、qrels 二值、test 只跑一次） | 协议纪律写死，面试照说 |
| 重写漂移（指代消解错，循环节点头号失败模式） | 重合度自检 + trace 记改写前后原文，人工抽检 drift |
| 循环跑飞 / 费用爆炸（每 query 约 1-6 次 LLM 调用） | max_iterations 封顶 + 评测前先 10 条 smoke |
| judge 校准差（1-10 分全堆中间） | 0/1/2 三档 + 人工抽 20% 校准 |
| ragas 依赖事故（import 即炸） | 自写 judge，定义对齐其公开文档 |

## 附：三分钟自测

读完这篇，你应该能用大白话回答：

1. **这个项目和普通 RAG 的区别是什么？**——普通 RAG 找到资料就生成；这个项目多两道质检（相关性、充分性），不过关就改写重查，3 次不过就拒答。
2. **judge 和 rerank 为什么不合并成一个节点？**——一个判"每篇相关不相关"（局部），一个判"合起来够不够"（全局）；先用便宜的后用贵的。
3. **怎么证明纠错循环真的有用？**——公开人工标注基准上做同题 A/B，报 "X% → Y%"，数字全部能从 trace 里找到出处。

三个都答得上，全景就看清了。
